# เว็บไซต์ศูนย์ป่าไม้ขอนแก่น

เอกสารนี้อธิบายโครงสร้าง การตั้งค่า และวิธีดูแลเว็บไซต์ศูนย์ป่าไม้ขอนแก่น อ้างอิงจากโค้ดหน้า `index.html` และข้อมูลหน้า `about.html` ที่ได้รับ

> **ขอบเขตเอกสาร:** ยังไม่มีซอร์สโค้ดฉบับจริงของ `login.html`, `admin.html` และ `Code.gs` รายละเอียดของไฟล์เหล่านั้นจึงเป็นคำอธิบายเบื้องต้น ต้องตรวจสอบให้ตรงกับระบบที่ใช้งานจริงก่อนนำไปพัฒนาหรือเผยแพร่

## 1. โครงสร้างไฟล์เว็บไซต์

ตัวอย่างโครงสร้างไฟล์:

```text
website/
├── index.html       # หน้าแรก ข่าวสาร กิจกรรม และเอกสาร
├── about.html       # ข้อมูลองค์กร บุคลากร และผลการปฏิบัติงาน
├── login.html       # หน้าเข้าสู่ระบบเจ้าหน้าที่ (ยังไม่มีซอร์สโค้ด)
├── admin.html       # หน้าจัดการข้อมูล (ยังไม่มีซอร์สโค้ด)
└── Code.gs          # Google Apps Script API (ยังไม่มีซอร์สโค้ด)
```

เว็บไซต์ส่วนหน้าใช้ HTML, CSS และ JavaScript โดยโหลด Bootstrap, Font Awesome และฟอนต์ Sarabun จาก CDN ส่วนข้อมูลข่าวและเอกสารเชื่อมต่อผ่าน Google Apps Script API ตาม URL ที่กำหนดในหน้าเว็บ

## 2. เทคโนโลยีที่ใช้

- **HTML** สำหรับโครงสร้างหน้าเว็บ
- **CSS** สำหรับสี รูปแบบ และการจัดหน้า
- **JavaScript** สำหรับโหลดข้อมูล API แบ่งหน้า และเปิดหน้าต่างรายละเอียด
- **Bootstrap 5.3** สำหรับ responsive layout, modal, accordion และ component ต่าง ๆ
- **Font Awesome 6.4** สำหรับไอคอน
- **Google Fonts — Sarabun** สำหรับตัวอักษรภาษาไทย
- **Google Apps Script และ Google Sheets** สำหรับ API และฐานข้อมูล หากระบบหลังบ้านใช้ตามโครงสร้างที่กล่าวถึง

## 3. หน้าแรก — `index.html`

### 3.1 ส่วนประกอบของหน้า

หน้าแรกในโค้ดที่ได้รับประกอบด้วย:

1. **แถบนำทาง**
   - ลิงก์หน้าแรก
   - ลิงก์ข้อมูลองค์กร
   - ลิงก์ไปยังข่าวสารและคลังเอกสารในหน้าเดียวกัน
   - ลิงก์เข้าสู่ระบบเจ้าหน้าที่
   - ลิงก์ “ดึงลิงก์ (URL)” ไปยัง Google Apps Script

2. **ส่วนหัว Hero**
   - แสดงชื่อ “ศูนย์ป่าไม้ขอนแก่น”
   - แสดงชื่อกรมและกระทรวง
   - ใช้ภาพพื้นหลังและ overlay สีเข้ม

3. **ข่าวสารและกิจกรรม**
   - โหลดข้อมูลด้วย API action `getNews`
   - แสดงข่าวครั้งละ **9 รายการ**
   - มีปุ่มแบ่งหน้า
   - เปิดรายละเอียดข่าวใน modal
   - มีลิงก์แชร์ไปยัง Facebook, LINE และ X

4. **ดาวน์โหลดเอกสารราชการ**
   - โหลดข้อมูลด้วย API action `getDocuments`
   - แสดงชื่อเอกสาร หมวดหมู่ ผู้เผยแพร่ วันที่ และปุ่มดาวน์โหลด

5. **Popup ข่าวล่าสุด**
   - เปิดแสดงข่าวลำดับแรกตามการเรียงข้อมูล
   - มีภาพ ชื่อข่าว เนื้อหาย่อ และปุ่มอ่านรายละเอียด

6. **Footer**
   - แสดงข้อมูลติดต่อ
   - แสดงสถิติผู้เข้าชมจาก Counter12
   - แสดงลิงก์หน่วยงานที่เกี่ยวข้อง

### 3.2 จำนวนข่าวต่อหน้า

ใน JavaScript ของ `index.html` กำหนดจำนวนข่าวต่อหน้าไว้ดังนี้:

```javascript
const NEWS_PER_PAGE = 9;
let currentNewsPage = 1;
let globalNewsList = [];
```

หากต้องการเปลี่ยนจำนวนรายการต่อหน้า ให้แก้ค่าของ `NEWS_PER_PAGE` เช่น:

```javascript
const NEWS_PER_PAGE = 9;
```

ฟังก์ชัน `renderNewsPage()` ใช้ `slice()` เลือกรายการที่จะแสดงตามหน้าปัจจุบัน ส่วน `changeNewsPage()` เปลี่ยนหน้าและเลื่อนหน้าจอกลับไปยังส่วนข่าว

### 3.3 รูปแบบการเรียงข่าว

โค้ดเรียงข่าวตาม `sort_order` จากน้อยไปมาก หากไม่มีลำดับจะใช้ค่า `999` และนำวันที่ `created_at` มาช่วยเรียงรายการที่มีลำดับเท่ากัน

ควรตรวจสอบให้ `sort_order` ในข้อมูลเป็นตัวเลข และ `created_at` เป็นวันที่ที่ JavaScript อ่านได้ถูกต้อง

### 3.4 ข้อมูลที่ข่าวควรมี

โค้ดหน้าแรกอ้างถึงข้อมูลข่าวเหล่านี้:

| ฟิลด์ | วัตถุประสงค์ |
|---|---|
| `news_id` | รหัสข่าว ใช้ค้นหาและเปิดรายละเอียด |
| `title` | ชื่อข่าว |
| `content` | เนื้อหาข่าว |
| `author` | ผู้จัดทำหรือผู้เผยแพร่ |
| `created_at` | วันที่ข่าว |
| `image_url` | URL ภาพข่าว อาจมีหลาย URL คั่นด้วยเครื่องหมายจุลภาค |
| `sort_order` | ลำดับการแสดงผล |

ชื่อฟิลด์ต้องตรงกับข้อมูลที่ API ส่งกลับมา หากชื่อใน Google Sheets หรือ API ต่างจากนี้ ต้องแก้ JavaScript หรือการแปลงข้อมูลใน Apps Script ให้ตรงกัน

### 3.5 รายละเอียดข่าวและการแชร์

เมื่อเรียก `openNewsDetail(newsId)` ระบบค้นหารายการจาก `globalNewsList` แล้วนำข้อมูลไปแสดงใน modal ได้แก่:

- ชื่อข่าว
- วันที่
- ผู้เขียน
- เนื้อหา
- รูปภาพประกอบ
- ลิงก์แชร์

ลิงก์ที่แชร์ใช้ URL ปัจจุบันและเพิ่มรหัสข่าวในรูปแบบ `#news=รหัสข่าว`

### 3.6 ข้อมูลเอกสาร

โค้ดหน้าแรกตรวจชื่อฟิลด์เอกสารหลายรูปแบบเพื่อรองรับข้อมูล เช่น:

| ฟิลด์ที่อ่าน | ความหมาย |
|---|---|
| `title` หรือ `doc_title` | ชื่อเอกสาร |
| `category` | หมวดหมู่ |
| `uploaded_by` หรือ `author` | ผู้เผยแพร่ |
| `created_at` หรือ `date` | วันที่ |
| `file_url` หรือ `url` | ลิงก์ไฟล์ |

แนะนำให้ใช้ชื่อฟิลด์มาตรฐานรูปแบบเดียวกันทั้งระบบ เพื่อลดความสับสนและปัญหาข้อมูลไม่แสดง

## 4. หน้าองค์กร — `about.html`

หน้าองค์กรใช้แสดงข้อมูลแนะนำหน่วยงาน โดยเนื้อหาที่จัดไว้ประกอบด้วย:

- ประวัติความเป็นมา
- สถิติภาพรวมป่าชุมชน
- โครงสร้างหน่วยงาน
- ทำเนียบบุคลากร
- ผลการปฏิบัติงานประจำปีงบประมาณ พ.ศ. 2569
- โครงการเงินนอกงบประมาณ
- ข้อมูลติดต่อและลิงก์หน่วยงานที่เกี่ยวข้อง

### 4.1 สถิติภาพรวมที่ปรากฏในข้อมูล

| รายการ | จำนวน |
|---|---:|
| ป่าชุมชนที่รับผิดชอบ | 253 ป่าชุมชน |
| พื้นที่ป่าชุมชนรวม | 44,193 ไร่ |
| คณะกรรมการจัดการป่าชุมชน | 2,530 คน |

ควรระบุวันที่อ้างอิงของสถิติ และตรวจสอบว่าตัวเลขยังเป็นปัจจุบันก่อนเผยแพร่

### 4.2 โครงสร้างหน่วยงานที่ปรากฏในข้อมูล

- สำนักจัดการทรัพยากรป่าไม้ที่ 7 (ขอนแก่น)
- ศูนย์ป่าไม้ขอนแก่น
- ฝ่ายบริหารทั่วไป
- ฝ่ายประสานและส่งเสริมงานป่าไม้
- หน่วยป้องกันและพัฒนาป่าไม้ที่ระบุ ได้แก่ ภูเวียง มัญจาคีรี แวงใหญ่ เขาสวนกวาง และภูผาม่าน

โปรดตรวจสอบชื่อและจำนวนหน่วยงานกับข้อมูลทางการก่อนเผยแพร่

### 4.3 ทำเนียบบุคลากร

ข้อมูลที่ให้ไว้ระบุ:

- ข้าราชการ 3 ราย
- พนักงานราชการ 15 ราย
- รวมบุคลากร 18 ราย

ตัวอย่าง URL ภาพจาก Google Drive ที่ใช้ใน `src`:

```html
<img
    src="https://drive.google.com/thumbnail?id=1uNRDwVUr7DlOdPjwyjeVaPk8l2DGd9fa&sz=w1600"
    alt="ทำเนียบบุคลากรศูนย์ป่าไม้ขอนแก่น"
    class="img-fluid rounded"
    loading="lazy">
```

หากภาพไม่แสดง ให้ตรวจสอบสิทธิ์ไฟล์ใน Google Drive:

1. เปิดไฟล์ภาพใน Google Drive
2. กด **แชร์**
3. ตั้ง **การเข้าถึงทั่วไป** เป็น **ทุกคนที่มีลิงก์**
4. ตั้งสิทธิ์เป็น **ผู้ดู**
5. ทดลองเปิดลิงก์ภาพในแท็บใหม่
6. รีเฟรชหน้าเว็บไซต์

หากยังไม่แสดง ให้ดาวน์โหลดภาพแล้ววางไว้ในพื้นที่จัดเก็บที่เว็บไซต์เข้าถึงได้ หรือใช้ระบบฝากภาพที่อนุญาตให้แสดงภาพจากเว็บไซต์ภายนอก

## 5. หน้าเข้าสู่ระบบ — `login.html`

ไฟล์ `login.html` ยังไม่ได้รับ จึงยังยืนยันไม่ได้ว่ามีหน้าตา ฟิลด์ หรือวิธีเข้าสู่ระบบแบบใด

หากเชื่อมต่อกับ Apps Script API ตามโครงสร้างเดิม ควรตรวจสอบว่า:

- หน้าเว็บส่งชื่อ action สำหรับเข้าสู่ระบบตรงกับที่ `Code.gs` รองรับ
- ฟิลด์ชื่อผู้ใช้และรหัสผ่านตรงกับ API
- ระบบตรวจสอบสถานะบัญชีและสิทธิ์ผู้ใช้งาน
- เมื่อเข้าสู่ระบบสำเร็จ มีการจัดการ session หรือ token อย่างเหมาะสม
- เมื่อเข้าสู่ระบบไม่สำเร็จ แสดงข้อความที่ไม่เปิดเผยข้อมูลระบบมากเกินไป

**ข้อควรระวัง:** ไม่ควรจัดเก็บรหัสผ่านเป็นข้อความธรรมดาใน Google Sheets สำหรับระบบใช้งานจริง ควรใช้ระบบยืนยันตัวตนที่ปลอดภัยและจำกัดสิทธิ์เข้าถึงข้อมูลผู้ใช้

## 6. หน้าแอดมิน — `admin.html`

ยังไม่มีซอร์สโค้ด `admin.html` ฉบับจริง จึงยังยืนยันเมนูและฟังก์ชันทั้งหมดไม่ได้

หากหน้าหลังบ้านใช้ร่วมกับเว็บไซต์ตามที่กล่าวถึง ควรตรวจสอบฟังก์ชันเหล่านี้:

- ดูจำนวนข่าว เอกสาร และสไลด์
- เพิ่ม แก้ไข และลบข่าว
- กำหนดวันที่และลำดับข่าว
- เพิ่มและลบเอกสาร
- เพิ่มและแก้ไขสไลด์
- ดูประวัติการใช้งานระบบ
- จำกัดการใช้งานตามสิทธิ์เจ้าหน้าที่

จำนวนข่าวที่แสดงในหน้าแอดมินเป็นคนละค่ากับหน้าแรกได้ ตัวอย่างเช่น หน้าแรกแสดง 9 ข่าวต่อหน้า ส่วนหน้าแอดมินแสดง 10 ข่าวต่อหน้า

## 7. Google Apps Script API

หน้า `index.html` กำหนด URL API ดังนี้:

```javascript
const API_URL = "https://script.google.com/macros/s/AKfycbzn1IbL2o832StUyTrLyGDTt0DSYM-2gY3VWsSZwfxk4gnJ7c1NeF-lZbLlvQ5voTzXnQ/exec";
```

URL นี้เป็นค่าที่ปรากฏในโค้ดที่ได้รับ หากมีการเปลี่ยน deployment ต้องเปลี่ยน URL ในทุกหน้าที่เรียก API ให้ตรงกัน

หน้าแรกเรียก action ต่อไปนี้:

| Action | ใช้ทำอะไร |
|---|---|
| `getSlides` | โหลดสไลด์ |
| `getNews` | โหลดข่าว |
| `getDocuments` | โหลดเอกสาร |
| `getVisitors` | อ่านข้อมูลผู้เข้าชม |
| `recordVisit` | บันทึกการเข้าชม |

ชื่อ action และรูปแบบข้อมูลจริงต้องตรวจสอบจาก `Code.gs` เพราะยังไม่มีโค้ด Apps Script ฉบับจริงในเอกสารนี้

### URL “ดึงลิงก์ (URL)”

ในแถบนำทางมีลิงก์ไปยัง Apps Script อีก URL หนึ่ง ซึ่งไม่ตรงกับค่า `API_URL` ในสคริปต์:

```text
URL ในลิงก์เมนู: AKfycbwdqyqKrvJWU0zXcrX6NEDXInlNrBx3uvdfd-2rPNr99YfCH5E9i_0eLjHVzg54NL3s
URL ใน API_URL:   AKfycbzn1IbL2o832StUyTrLyGDTt0DSYM-2gY3VWsSZwfxk4gnJ7c1NeF-lZbLlvQ5voTzXnQ
```

โปรดตรวจสอบว่าเป็น deployment ที่ตั้งใจใช้คนละตัวหรือไม่ หากควรใช้ตัวเดียวกัน ให้แก้ URL ให้ถูกต้องก่อนเผยแพร่

## 8. Google Sheets และรูปแบบข้อมูล

หาก `Code.gs` ใช้ Google Sheets เป็นฐานข้อมูล ให้ตรวจสอบชื่อชีตและหัวคอลัมน์กับโค้ด Apps Script ก่อนใช้งาน ตารางต่อไปนี้เป็น **ตัวอย่างฟิลด์ที่หน้าเว็บคาดว่าจะได้รับ** ไม่ใช่การยืนยันว่าเป็นโครงสร้างชีตจริง:

### ข่าว

| ฟิลด์ที่หน้าเว็บใช้งาน |
|---|
| `news_id` |
| `title` |
| `content` |
| `author` |
| `created_at` |
| `image_url` |
| `sort_order` |

### สไลด์

| ฟิลด์ที่หน้าเว็บใช้งาน |
|---|
| `title` |
| `image_url` |
| `sort_order` |

### เอกสาร

| ฟิลด์ที่หน้าเว็บใช้งาน |
|---|
| `title` หรือ `doc_title` |
| `category` |
| `uploaded_by` หรือ `author` |
| `created_at` หรือ `date` |
| `file_url` หรือ `url` |

หัวคอลัมน์ใน Google Sheets ต้องสอดคล้องกับการอ่านข้อมูลใน `Code.gs` และชื่อฟิลด์ JSON ที่ส่งกลับมายังหน้าเว็บ

2. บันทึกหน้าเว็บเป็นไฟล์ HTML ตามชื่อ เช่น `index.html` และ `about.html`
3. วางไฟล์ไว้บน Web Hosting ที่รองรับ static website หรือ GitHub Pages
4. ตรวจให้ชื่อไฟล์และลิงก์ในเมนูตรงกัน
5. ทดลองเปิดหน้าเว็บไซต์บนคอมพิวเตอร์และโทรศัพท์

### 9.2 ตั้งค่า Google Apps Script

เมื่อมีโค้ด `Code.gs` ฉบับจริง:

1. เปิดโครงการ Google Apps Script ที่เชื่อมกับ Google Sheets
2. ตรวจสอบว่า action ที่หน้าเว็บเรียกมีอยู่จริง
3. บันทึกโค้ด
4. เลือก **Deploy → Manage deployments**
5. แก้ไข deployment หรือสร้าง deployment ใหม่ตามวิธีที่หน่วยงานกำหนด
6. Deploy เวอร์ชันล่าสุด
7. คัดลอก Web App URL
8. ใส่ URL ให้ตรงกันในทุกหน้าที่เรียก API
9. ทดสอบ API ด้วย action ที่ระบบรองรับ

### 9.3 ทดสอบหลังเผยแพร่

- เปิด `index.html` และตรวจว่าหน้าเว็บโหลดได้
- ตรวจว่าข่าวแสดงไม่เกิน 9 รายการต่อหน้า
- กดเปลี่ยนหน้าและตรวจว่ารายการข่าวเปลี่ยน
- เปิดข่าวและตรวจรายละเอียด รูปภาพ และปุ่มแชร์
- ตรวจตารางเอกสารและปุ่มดาวน์โหลด
- เปิด `about.html` และตรวจภาพบุคลากร
- ทดสอบการเข้าสู่ระบบและหน้าหลังบ้านเมื่อมีไฟล์จริง
- ตรวจ Console ของเบราว์เซอร์หากข้อมูลไม่โหลด

## 10. ปัญหาที่พบใน `index.html` ที่ได้รับ

### 10.1 URL ภาพพื้นหลังมีเครื่องหมาย `*`

ในโค้ดมี URL รูปภาพลักษณะนี้:

```text
https://images.unsplash.com/photo-*************-3b1817f69a2d...
```

เครื่องหมาย `*` ทำให้ URL ใช้งานไม่ได้ ต้องแทนด้วย URL ภาพที่ถูกต้องทั้งใน:

- `background` ของ `.hero-section-modern`
- ตัวแปร `defaultImg` ใน `renderNewsPage()`
- URL ภาพสำรองใน `openNewsDetail()`

### 10.2 โค้ดสไลด์อ้างถึง HTML ที่ถูกคอมเมนต์

มีการเรียก:

```javascript
loadSlides();
```

แต่ส่วน Carousel ที่มี `carouselInner`, `carouselIndicators` และ `heroA4Carousel` ถูกคอมเมนต์ไว้ หากไม่ได้เปิดใช้สไลด์ ให้เอาการเรียก `loadSlides()` ออก หรือเปิดส่วน HTML Carousel ให้สอดคล้องกับ JavaScript

### 10.3 ฟังก์ชันนับผู้เข้าชมยังไม่ถูกเรียก

มีฟังก์ชัน `trackVisitor()` แต่ในโค้ดที่ได้รับไม่พบการเรียกใช้งาน และฟังก์ชันอ้างถึง element:

```text
footerVisitorCount
```

แต่ Footer ที่ส่งมาไม่พบ element ที่มี `id="footerVisitorCount"` จึงควรเลือกอย่างใดอย่างหนึ่ง:

- เพิ่ม element สำหรับแสดงจำนวนผู้เข้าชม และเรียก `trackVisitor()` เมื่อหน้าโหลด
- หรือเอาฟังก์ชันนับผู้เข้าชมออก หากใช้ Counter12 แทนอยู่แล้ว

### 10.4 ข้อความที่แทรกด้วย `innerHTML`

ข่าวและเอกสารถูกนำมาแทรกผ่าน `innerHTML` หากข้อมูลมาจากผู้ใช้หรือระบบหลังบ้าน ควร escape ข้อความก่อนแสดง เพื่อป้องกัน HTML หรือ script ที่ไม่พึงประสงค์

### 10.5 เอฟเฟกต์หิมะ

ฟังก์ชัน `initSnowEffect()` สร้างหิมะ 40 ชิ้นทุกครั้งที่เปิดหน้า อาจเพิ่มภาระบนโทรศัพท์หรือรบกวนการอ่าน หากไม่จำเป็นสามารถลดจำนวน ปิดเอฟเฟกต์ หรือรองรับการตั้งค่าลดการเคลื่อนไหวของผู้ใช้

## 11. ข้อมูลที่ควรตรวจสอบก่อนเผยแพร่

### ที่อยู่

ข้อมูลที่ปรากฏก่อนหน้านี้มีทั้ง **25/4** และ **255/4** จึงยังสรุปไม่ได้ว่าเลขใดถูกต้อง ควรตรวจสอบที่อยู่จริงกับหน่วยงานก่อนใส่ใน Footer

### โทรศัพท์

ควรตรวจสอบรูปแบบหมายเลข `043-330381 - 115` หรือ `043-330-381-2 ต่อ 115` กับหน่วยงาน และเลือกใช้รูปแบบที่เป็นทางการแบบเดียวกันทุกหน้า

### อีเมลและ Facebook

ข้อมูลตัวอย่างมีเครื่องหมาย `*` ปกปิดบางส่วน เช่น อีเมลและ Facebook URL ต้องแทนด้วยลิงก์จริงก่อนเผยแพร่ ห้ามใช้ URL ที่มีเครื่องหมายปกปิดเป็นลิงก์จริง

### สถิติ บุคลากร และผลการปฏิบัติงาน

ตรวจจำนวนบุคลากร สถิติพื้นที่ ชื่อหมู่บ้าน งบประมาณ ระยะทาง และปีงบประมาณให้ตรงกับข้อมูลทางการก่อนนำขึ้นเว็บไซต์

## 12. ความปลอดภัยและการดูแลรักษา

- อย่าเผยแพร่รหัสผ่านหรือข้อมูลส่วนบุคคลที่ไม่จำเป็น
- จำกัดสิทธิ์ผู้แก้ไข Google Sheets และ Apps Script
- ตรวจสอบสิทธิ์ Web App ก่อนเปิดให้ผู้ใช้เข้าถึง
- สำรอง Google Sheets ก่อนเปลี่ยนหัวคอลัมน์หรือโครงสร้างข้อมูล
- ใช้ HTTPS สำหรับเว็บไซต์และลิงก์ภายนอก
- ใช้ `rel="noopener"` กับลิงก์ที่เปิดแท็บใหม่
- ตรวจสอบและ escape ข้อมูลก่อนแสดงด้วย `innerHTML`
- อัปเดต URL API ให้ตรงกับ deployment ที่ใช้งานจริง

## 13. ไฟล์ที่ยังต้องเพิ่มเพื่อให้เอกสารครบทั้งระบบ

| ไฟล์ | สถานะ | สิ่งที่ต้องทำ |
|---|---|---|
| `index.html` | ได้รับโค้ดแล้ว | ตรวจ URL ภาพ, API และฟังก์ชันสไลด์/ผู้เข้าชม |
| `about.html` | มีข้อมูลจากบทสนทนา | ตรวจข้อมูลติดต่อ สถิติ และภาพบุคลากร |
